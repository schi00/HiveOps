# Deployment Notes - v1.1 Incident effectiveness & triage

**Component:** Support / incident triage KPI, fingerprint dedupe, dual user/IT responses, KB embedding column, auto-workflow triage gating.

## Database (run before app deploy)

Apply in order after v1.0 (if not already applied):

```bash
sqlcmd -S <server> -d <database> -i db/migrations/V1.1__IncidentEffectivenessAndKbEmbedding.sql
```

**New columns**

- `Incidents`: `TriageConfidence`, `Fingerprint`, `OccurrenceCount`, `ExtractedEntitiesJson`, `FinalUserResponse`, `TechnicalDiagnosticNote`, `ResolutionMode`, `EligibleForEffectivenessKpi`
- `KbArticles`: `EmbeddingVector` (optional; semantic KB ranking uses it when populated)

## API

- `GET /api/support/effectiveness-metrics?windowDays=28` — KPI snapshot (see `docs/architecture/incident-effectiveness-kpi.md`).

## Operational notes

- Until `KbArticles.EmbeddingVector` is backfilled, triage KB grounding falls back to keyword scoring for articles without vectors.
- `DiagnosticLogs` with `StepName = kpi.incident_resolved` records resolution mode for audit/replay.
