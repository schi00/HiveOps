## Deployment Steps

### Step 1: Database Migration (Run First)

**Priority:** CRITICAL - Must run before application deployment

```bash
# Using sqlcmd (Windows)
sqlcmd -S <server-name> -d <database-name> -i db/migrations/V1.0__ApiDriftDetection.sql -o migration.log

# Using Azure Data Studio or SSMS
-- Open db/migrations/V1.0__ApiDriftDetection.sql
-- Execute against target database
-- Verify output: "Migration V1.0__ApiDriftDetection completed successfully."
```

**Verification:**
```sql
-- Check table exists
SELECT * FROM sys.tables WHERE name = 'ApiDependencies';

-- Check indexes
SELECT * FROM sys.indexes WHERE object_id = OBJECT_ID('dbo.ApiDependencies');
```

### Step 2: Application Deployment

**Option A: Docker Deployment**
```bash
# Build image
docker build -t hiveops:v1.0.0 .

# Deploy to staging first
docker run -d --name hiveops-staging \
  -e ASPNETCORE_ENVIRONMENT=Staging \
  -p 8080:8080 \
  hiveops:v1.0.0

# Verify health
curl http://localhost:8080/health

# Deploy to production (rolling update)
docker service update --image hiveops:v1.0.0 hiveops_prod
```

**Option B: IIS / Windows Server**
```powershell
# Stop application pool
Stop-WebAppPool -Name "HiveOps"

# Deploy new binaries
Copy-Item -Path ".\artifacts\v1.0.0\*" -Destination "C:\inetpub\wwwroot\hiveops" -Recurse -Force

# Start application pool
Start-WebAppPool -Name "HiveOps"

# Verify
Invoke-WebRequest -Uri "http://localhost/health" -UseBasicParsing
```

**Option C: Azure App Service**
```bash
# Deploy via ZIP
cd src/HiveOps.Api
dotnet publish -c Release -o ./publish
zip -r ../../deploy/hiveops-v1.0.0.zip ./publish

# Upload to Azure
az webapp deployment source config-zip \
  --resource-group <rg-name> \
  --name <app-service-name> \
  --src ../../deploy/hiveops-v1.0.0.zip
```

## Monitoring & Alerts

### New Log Patterns to Watch

```
# Learning mode (expected during first calls)
[API_DRIFT] New endpoint detected in learning mode

# Healthy operation
[API_DRIFT] Endpoint graduated from learning mode
[API_DRIFT] Endpoint recovered to healthy state

# Drift detection (requires attention)
[API_DRIFT] Contract drift detected!

# Errors (should not impact users)
[API_DRIFT] Fail-safe: Drift detection failed but response will continue
```

### Metrics to Monitor

| Metric | Healthy Threshold | Alert Threshold |
|--------|-------------------|-----------------|
| Drift detection errors | < 0.1% | > 1% |
| Learning mode registrations | N/A | Spikes indicate new integrations |
| Drift incidents | 0 | Any drift requires review |

## Rollback Procedure

### If Critical Issue Detected

**Step 1: Stop drift detection**
```csharp
// Temporary: Remove handler from HttpClient pipeline
// Edit Program.cs and comment out:
// .AddHttpMessageHandler<ApiContractObserverHandler>();
```

**Step 2: Revert to previous version**
```bash
# Docker
docker service update --image hiveops:v0.9.0 hiveops_prod

# IIS
# Restore from backup
Copy-Item -Path "C:\backups\hiveops-v0.9.0\*" -Destination "C:\inetpub\wwwroot\hiveops" -Recurse -Force
Restart-WebAppPool -Name "HiveOps"
```

**Step 3: Database (optional - table can remain)**
```sql
-- Only if absolutely necessary
-- Note: This will lose drift detection history
-- DROP TABLE [dbo].[ApiDependencies];
```

**Rollback Time:** < 5 minutes

## Troubleshooting

### Issue: Dashboard shows "Error al cargar APIs"

**Check:**
1. User is authenticated (token in localStorage)
2. Tenant is selected (X-Tenant-Id header present)
3. User has appropriate role (Admin or SuperAdmin)

**Resolution:**
- Clear browser cache
- Re-login to dashboard
- Check browser console for CORS errors

### Issue: No drift detection occurring

**Check:**
1. Responses have `Content-Type: application/json`
2. Tenant context is resolved (check logs for "Tenant context not resolved")
3. Handler is registered (check Program.cs)

**Resolution:**
- Verify HttpClient is using named client "OutboundWebhook" or "ApiDriftDetection"
- Check that ApiContractObserverHandler is in DI container

### Issue: Memory issues with large payloads

**Check:**
- Memory usage during high traffic
- Large JSON responses (>10MB)

**Resolution:**
- Drift detection can be disabled for specific endpoints
- Consider excluding file download endpoints
- Monitor MemoryStream allocations
